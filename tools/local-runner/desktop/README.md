# Bankai Companion for Windows

The desktop companion gives the local runner a Bankai-style setup and control UI. It pairs the computer with a Bankai workspace, checks Docker/Jenkins/Quincy readiness, starts and stops the Quincy local Jenkins stack and API, starts the Bankai polling runner, shows live redacted service output, and opens Jenkins in a restricted in-app window.

## Developer setup

Requirements: Windows 10/11, Node.js 20+, Docker Desktop, Git, Python 3.12, OpenSSL, and the adjacent `quincy-security-engine` checkout with its `.venv` dependencies installed.

If the Quincy virtual environment is not prepared yet:

```powershell
cd C:\path\to\quincy-security-engine
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
```

```powershell
cd tools\local-runner\desktop
npm ci
npm run dev
```

`npm run build` builds the renderer assets. `npm run package:win` creates an unpacked Windows app directory for local preview.

To create a Windows NSIS installer:

```powershell
npm run dist:win
```

The installer is written to `release`. This developer build is unsigned. Windows may show an unknown publisher prompt; do not distribute it to end users as an approved release. A production release needs an organization-controlled code-signing certificate and signed update channel.

## First run

1. Select the Quincy checkout and add exact public repositories as `owner/repo`, one per line. Save settings.
2. In Bankai's **Jenkins Verification** page, create a one-time pairing code.
3. In the companion, enter the Bankai backend URL, code, and local Quincy `SERVICE_API_TOKEN`. Generate a token in the app or enter an existing one. Pairing stores it in Windows Credential Manager and clears the form.
4. Start Jenkins. When it is healthy, start the Quincy API. The companion reads the Jenkins token generated by the local stack and passes it only to the local Quincy process.
5. Start the companion. In Bankai's web app, choose **Run with Jenkins** for the intended remediation attempt.

The Jenkins browser is limited to `https://localhost:8443`, validates the local certificate against the configured CA, and never receives the API token. Use the Jenkins UI login if prompted.

## Local data and trust

- Nonsecret endpoints, repository allowlist, and checkout path are stored in Electron's per-user settings directory.
- Pairing credentials are stored in Windows Credential Manager by the existing runner.
- The Quincy service and Jenkins API tokens are supplied only to local processes. They are not sent to Bankai.
- The local controller remains loopback-only. The companion makes outbound HTTPS requests to Bankai.
- Local results are evidence only. They do not set `VERIFIED` or publish trusted GitHub success from the desktop.

This companion currently supports the local Quincy/Jenkins profile and public repositories. It does not yet provide a signed production update channel, tray lifecycle, credential rotation UI, resource-usage policy controls, or hardened VM-backed execution for malicious repository code.
